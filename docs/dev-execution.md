# 개발 업무 지휘 체계

근거: 본부장 「VTM AI COMPANY — 개발자 실행체계 변경 공지」(2026-08-20)

## 지휘 체계

```
본부장
  → 김서윤 비서실장 / Google Drive SSOT   (기획·정책·요구사항 확정)
    → 서지윤 실장                          (개발 실행 총괄)
      → 개발자                             (Work Order 기준 수행)
        → 테스트 / 배포 / 결과
```

## 서지윤 실장의 개발 총괄 범위

1. 확정 기획문서 확인
2. 개발업무 분해
3. 담당 개발자 선정
4. **Work Order 전달** — 개발자의 유일한 공식 실행 근거
5. 결과 검수
6. REWORK 지시
7. 통합 · 테스트 · 배포 관리

## 개발자에게 적용되는 규칙

개발자는 **서지윤 실장이 전달한 Work Order 를 기준으로만** 실행한다.

- 김서윤 비서실장의 **초안·아이디어 문서를 보고 임의로 개발을 시작하지 않는다.**
- VTM OS 의 권한 범위 안에서만 실행한다. **권한 우회 금지.**
- 요구사항을 임의로 확대하거나 축소하지 않는다.
- acceptance criteria 를 완료 기준으로 사용한다.
- **테스트되지 않은 상태를 완료로 보고하지 않는다.**
- 실패·차단 시 BLOCKED 사유를 명시한다.
- 수정 요청 시 REWORK 를 수행한다.
- 배포가 완료조건이면 **실제 접속 가능한 URL 까지 검증한다.**
- 결과와 증거는 지정된 Drive / Repository 에 남긴다.

## 개발 업무 완료 기준

**코드 작성만으로 완료가 아니다.**

필요한 경우 아래 전 구간을 통과해야 완료다.

```
구현 → 테스트 → 빌드 → 모바일/PC 검증
     → Preview/Production 배포 → URL 확인 → 결과 보고
```

| 단계 | 확인 사항 |
|---|---|
| 구현 | 요구사항 범위 그대로. 확대·축소 없음 |
| 테스트 | 실제 실행. "통과할 것으로 보임"은 테스트가 아니다 |
| 빌드 | 빌드 성공 로그 |
| 모바일/PC 검증 | 완료조건에 포함된 경우 양쪽 모두 |
| 배포 | Preview 또는 Production, 완료조건이 지정한 쪽 |
| URL 확인 | **실제 접속해서 확인.** 배포 성공 로그만으로는 부족하다 |
| 결과 보고 | Executive Report (`docs/executive-report.md`) |

서지윤 실장은 위 단계 중 완료조건이 요구하는 지점까지 검증되지 않으면
`COMPLETE` 로 종결하지 않는다. `PARTIAL` 또는 `BLOCKED` 로 보고한다.

## REWORK

검수에서 완료기준 미달이 확인되면 서지윤 실장이 REWORK 를 지시한다.

- 무엇이 어느 기준에서 미달인지 **항목 단위로** 명시한다.
- "다시 해라"는 REWORK 지시가 아니다.
- REWORK 범위를 원래 요구사항 밖으로 넓히지 않는다.
